# 官方私聊来电收尾

2026-10-15 实机已观察到：独立Host拒绝缺失依赖的首次来电后，官方QQ仍保留来电窗口；健康重拨时，同一官方文档收到第二次20006，随后收到本SDK的Reject9 ACK0，而独立Host接听ACK0后未入房。证据为`host382-official-reject-ack-comparison.safe.json`。ACK不含scene或peer，不能单独授权操作窗口。

`agent/official-private-invite.cjs`提供独立的生产控制器，不从诊断观察报告取得授权。它在Agent启动时监听新的、固定QQ renderer `/av` 文档中的原生来包，不替换SDK方法。启动时已有的AV文档不参与收尾。每个文档只认第一次20006；新邀请、接听/入房/结束相关来包或真实指针/键盘操作都会阻止旧窗口操作。

认证IPC的`privateInviteLifecycle`只接受固定操作、原始类型1邀请证据、当前双方UID/机器人UIN及匹配的七字段来电参数，不接受脚本、窗口ID或选择器。Agent要求当前注册序列和原生邀请序列仍有效；窗口中的原生来电必须指向当前机器人，参数与独立Host解码结果一致，且只有一个新鲜候选文档。异步安装前捕获的邀请不能被后来的Kernel邀请重新标记。

拒接收尾通过固定中文来电界面的唯一可见“邀请你语音通话”“接听”“挂断”入口组合识别接收状态，再从唯一、有限尺寸的单动作区域解析实际按钮或SVG图标父控件，触发官方现有“挂断”处理。动作在固定截止时间后不执行；只有对应AV文档销毁或退出原路线，且邀请仍未改变，才报告文档结束。无法识别、多个候选、导航/身份变化或执行结果不确定，均保留占用。该路径不发送猜测的Native10/11。

Bridge先等独立Host的当前Reject ACK，再完成上述官方文档收尾，最后取得新的Host房间不存在证明；三者缺一不能释放拒接占用。接受通话只退休相应收尾资格，不操作UI，也不替代Native accept的原有围栏。断连停用控制器，renderer保留短租约兜底；关闭的窗口会从记录中移除，原始身份仅瞬时用于私有控制，状态报告只含固定计数。

Host388实测官方挂断后隐藏并保留AV文档，既有CallStore.hangup反汇编亦包含hide。因此新增独立的`official_private_invite_receiving_closed`完成类型：本次严格作用域动作后收到且仅收到一个官方Reject9 [0,空字符串] ACK，并观察到原先可见、非最小化窗口单次hide、无show；renderer须仍是原始邀请、无入房/新邀请/用户输入、结果新鲜且未超期限。只隐藏或只有ACK均不能完成。确认后重置本控制器监听epoch，新的原生邀请必须匹配新捕获；仍须Bridge获取新的Host空房间证明。该类型不声称文档已销毁。

文档复用时旧epoch停止标记会取消晚到安装；旧安装的后续清理仅针对旧epoch，不能误停新文档。renderer也独立验证固定AV路线，并在执行前复核期限，短租约不能延长动作截止时间。

同一次页内导航的开始与完成通知配对，仅在开始重置一次，并立即尝试安装；匹配完成通知不再删除期间捕获的新邀请。不同目标、无配对通知或完整导航仍独立重置。状态只额外给出有界导航计数，不保存导航URL或邀请身份。
