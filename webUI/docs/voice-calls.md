# WebUI Chat 语音通话

聊天页的「语音通话」入口先检查 Core 的 TTS 健康状态。TTS 未就绪时不能创建通话；ASR 不可用或麦克风权限被拒绝时，可以在转写栏打字，由 Bot 语音回复。麦克风需要浏览器的安全上下文（localhost 或 HTTPS）。

## 交互

- 自动收音，检测持续说话约 180 ms 后立即停止 Bot 当前播放；静音约 780 ms 后提交本段转写，单段最多 12 秒。
- 浏览器请求回声消除、降噪和自动增益。开口检测基于音量和持续时间，实际扬声器回声效果取决于浏览器和设备。
- 每次打断更新通话 generation；旧转写、旧回复、旧 TTS 和控制指令不能在新一轮播放。
- 多段回复排队播放，Live2D 动作随对应音频开始，口型由 Bot 播放音频的分析结果驱动。
- 主通话场景嵌入当前聊天内容区，替换文字消息区和输入框的可见视图；聊天页眉、侧栏、会话导航仍可用。文字消息 DOM 会保留，挂断或最小化后原样恢复。
- 通话转写默认收起，点击底部「转写」按钮展开；ASR 未就绪或麦克风不可用时自动展开，让用户直接输入。转写消息和文字输入框共用该栏。
- 最小化会返回文字聊天，通话和计时继续；聊天页眉显示「通话中」、计时和恢复/挂断入口。恢复后回到通话场景。挂断也会恢复文字聊天。
- 切换/新建会话，或删除当前通话所属会话时，先选择「继续通话」（留在原会话）或「挂断并切换」。
- 通话记录只显示当前聊天会话，按每次通话分组。刷新不会自动开启麦克风或重播历史。

## 上下文与记录

文字消息继续走现有 Planner 路径；每条通话输入沿用语音通话的 per-message bypass，直接进入 Core。两者使用当前会话的确定性 Core 身份 `webui_<conversation_id>`，因此共享该会话的 Core 上下文。发送前持久化请求路由，将回复固定到原始文字请求或通话及 generation；不能用“当前是否正在通话”猜测回复归属。

通话转写、Bot 回复与播放状态存于 `webUI/data/voice_calls.sqlite3`，与浏览器文字聊天历史分开。WebUI 不保存用户录音。迟到回复仍留在原通话记录中，但标记取消且不播放。删除聊天会话也删除其通话记录。8 秒心跳维持 30 秒租约；失联或 WebUI 重启后旧通话结束。

当前存储保护上限为每次通话 500 条消息、总计 5000 次通话，达到上限会明确拒绝新增，不静默删除转写；列表返回当前会话最近 100 次通话。请求路由和去重元数据按期限清理，不清理转写正文。

## 频繁打断

服务端仅对存在待生成回复或未播完回复的真实打断计数，重复 generation 请求不重复计数，普通聆听不计数。当前通话在 60 秒内累计 3 次打断后暂存一次反馈，提醒冷却 60 秒。反馈暂存最多 60 秒，挂断/失联/重启即清理。

反馈随下一条成功送达 Core 的有效通话输入进入回复提示，由 Bot 结合人设自然回应；转写失败不会提前消费反馈。不伪造普通用户消息，不单独播放一段提示去抢用户的话。

## Live2D

自动扫描适配器目录中有效模型，健康度通过后允许选择。浏览器独立持有渲染器，不操控桌面 Live2D 窗口；复用适配器的模型映射和控制管线。服务不健康、WebGL/模型加载失败或未启用时，显示聊天页 Bot 头像。

浏览器依赖和本地 Cubism Core 安装位置见 [live2d-web.md](live2d-web.md)。访问令牌模式通过鉴权 fetch 获取模型资源并转换为临时 blob URL，不把令牌写入图片地址。

`node --test webUI/tests/*.test.js`

浏览器验收使用独立临时页面：真实模型、正式通话面板，Core/TTS 响应模拟；不会启动或重启正式 Core/WebUI。真实麦克风、ASR、LLM、TTS 的完整通话需在更新后的服务运行时验证。
